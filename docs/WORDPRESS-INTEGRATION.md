## Источник истины контента

**Единственный источник истины по контенту и составу экранов — утверждённый макет Figma.**

Правила:
- тексты, количество блоков, подписи, CTA и изображения сверяются прежде всего с Figma;
- HTML-верстка в `html/` — технический источник структуры и CSS-классов, но не источник истины по контенту;
- старый сайт `arcticrc.ru` не используется для наполнения нового сайта;
- отсутствующий в Figma контент не переносим и не придумываем;
- если HTML или текущая тема расходятся с Figma, исправляем HTML/тему в сторону Figma;
- если desktop и mobile в Figma содержат разные значения, это фиксируется отдельно как расхождение самого макета и не скрывается.

## Порядок согласования

После каждого законченного этапа я указываю его ID, например: **AR-003 готов к проверке**.

После проверки Андрей может дать один из ответов:
- **«AR-003 согласовано»** — фиксируем статус **Согласовано**;
- **«AR-003 правки: …»** — фиксируем **Нужна правка** и список замечаний;
- **«AR-003 пока не проверял»** — оставляем **Готово к проверке**.

Следующий крупный шаблон начинаем после того, как предыдущий доведён хотя бы до состояния **Готово к проверке**. Так прогресс всегда виден по таблице и ни одна часть проекта не теряется.


## Архитектура контента

### Услуги

CPT `service` + taxonomy `service_direction`.

Целевой URL:

`/services/{direction}/{service}/`

Так структура остается масштабируемой и не требует отдельных PHP-файлов под каждую услугу.

### Проекты

CPT `project`.

План полей:
- заголовок;
- превью;
- регион/город;
- связанная услуга;
- краткое описание;
- основной контент;
- галерея;
- связанные услуги.

### Оборудование

`equipment` — служебная админ-сущность для карточек оборудования. Публичного архива и single-страниц у неё нет.

Аренда/продажа — обычные страницы WordPress. `equipment_mode` используется только как служебная taxonomy для фильтрации/организации карточек в админке.

## Ассеты

CSS и JS на первом этапе не пересобираем.

Все существующие файлы подключаются через `wp_enqueue_style()` / `wp_enqueue_script()`, версии — через `filemtime()`.

При переносе HTML:
- относительные пути к media заменяем на theme URI;
- внутренние HTML-ссылки заменяем на WordPress permalinks;
- статические `title`/meta убираем, SEO отдаем WordPress + Rank Math.

## Header / Footer

Сохраняем текущую разметку.

Динамические данные:
- WP menus;
- телефон/email;
- социальные ссылки;
- реквизиты;
- юридические ссылки;
- текущий год.

## Формы

Используем Contact Form 7 как движок отправки, при этом внешний вид остаётся из утверждённой BEM-верстки ArcticRC.

Реализация:
- CF7-формы создаются автоматически кодом;
- отдельные варианты: консультация и оборудование;
- статические формы из исходных HTML-шаблонов автоматически заменяются на CF7;
- сохраняются классы `enquiry-form*` и существующая стилизация;
- телефон форматируется существующим JS;
- согласие обязательно;
- `purpose` и `record_id` передаются скрытыми полями;
- модальная форма общая и выводится из `footer.php`;
- после успешной отправки модальное окно закрывается;
- адрес получателя берётся из глобального email сайта;
- если CF7 не активирован, администратор видит предупреждение.

CRM-интеграцию добавляем отдельно, если она потребуется.

## SEO и миграция

До релиза обязательно:
1. получить полный список URL старого сайта;
2. определить новый URL каждого документа;
3. сохранить URL где возможно;
4. для измененных адресов подготовить 301;
5. проверить title/description;
6. проверить H1-H3;
7. проверить canonical;
8. проверить sitemap Rank Math;
9. проверить robots;
10. проверить Schema.org отдельным проходом.

Старый сайт не является источником контента. Состав нового сайта определяется утверждёнными экранами Figma.

Формат таблицы миграции:

`old URL → new URL → type → status → redirect`

## Автоматическое наполнение

Проект должен разворачиваться уже наполненным по утверждённой верстке/макету.

Правила:
- без ручной кнопки импорта;
- при первом заходе в админку тема автоматически создаёт базовые страницы и записи;
- исходные тексты, изображения и ссылки берутся из утверждённой статической верстки в `html/` и `assets/`;
- пути к изображениям переводятся на ассеты темы автоматически;
- главная назначается автоматически;
- меню создаются и назначаются автоматически;
- глобальные ACF-настройки заполняются значениями из макета только если поле ещё пустое;
- последующие ручные изменения глобальных настроек не должны перетираться обновлением темы;
- для страниц из макета сохраняется исходная BEM-разметка без `wpautop`;
- визуальный результат после установки темы должен совпадать с утверждённым макетом без отдельного этапа ручного наполнения.

Текущие автоматические источники:
- `html/index.html` → Главная;
- `html/services.html` → архив услуг;
- `html/services-soil-testing.html` → услуга «Полевые испытания грунтов сваями»;
- `html/equipment-rent.html` → Аренда оборудования и спецтехники;
- `html/equipment-sale.html` → Продажа оборудования и спецтехники;
- `html/contacts.html` → Контакты.


### География на главной

Для блока `AR-103` предусмотрено два режима:

- **Картинка** — выводятся отдельные desktop/mobile изображения из Media Library.
- **Яндекс.Карта** — интерактивная карта загружается автоматически через JavaScript API Яндекс.Карт.

В ACF при выборе режима «Картинка» показываются поля изображений. При выборе «Яндекс.Карта» изображения скрываются и выводится пояснение, что карта загружается автоматически.

Настройки карты на главной:
- широта центра;
- долгота центра;
- масштаб;
- повторитель точек: название, широта, долгота.

API-ключ хранится глобально: **Сайт → Интеграции → API-ключ Яндекс.Карт**. Текущий ключ временный и должен быть заменён перед релизом.

Скрипт Яндекс.Карт подключается только на главной и только когда выбран режим карты.


### Правила ACF для страниц

Для всех страниц проекта используем единый подход:

- вкладки ACF располагаются вертикально слева (`placement: left`);
- первый экран считается обязательным и не имеет переключателя видимости;
- каждый следующий самостоятельный контентный блок получает переключатель **«Показывать блок»**;
- выключенный блок не рендерится на фронте;
- связанные с выключенным блоком внешние ресурсы не должны подключаться без необходимости;
- seed заполняет начальные значения, но никогда не должен повторно включать блок, который клиент выключил вручную.

Это правило применяется ко всем следующим шаблонам без отдельного напоминания.


### Карточки услуг

Единый источник данных для Главной и архива услуг:

- на Главной поле **«Услуги»** — Relationship к CPT `service`;
- название берётся из заголовка записи;
- изображение берётся из Featured Image;
- номер карточки рассчитывается автоматически по порядку;
- краткий список хранится в самой услуге;
- ссылка всегда ведёт на permalink выбранной услуги.

Отдельные поля картинки и номера в блоке Главной не используются.


### Настройки архива услуг

URL `/services/` — обычная WordPress-страница с шаблоном `page-services.php`. CPT `service` используется только для детальных услуг:

**Страницы → Услуги**

Доступно:
- H1 страницы;
- включение/отключение блока услуг;
- Relationship выбора услуг и их порядка;
- включение/отключение контактного блока;
- заголовок и описание контактов.

Карточки услуг используют данные самой записи: Title, Featured Image, краткий список и permalink. Номер формируется автоматически.

### Страницы аренды и продажи

`/equipment-rent/` и `/equipment-sale/` используют один шаблон `page-equipment.php`.

Каждая страница имеет собственные ACF-настройки:
- H1;
- описание главного экрана;
- desktop/mobile изображения главного экрана;
- основная кнопка;
- файл каталога;
- выбор и порядок equipment-записей;
- CTA;
- контактный блок;
- переключатели видимости для оборудования и контактов.

Карточка оборудования использует Title, Featured Image и список моделей из самой записи CPT `equipment`. Нумерация автоматическая.

Режимы `rent` / `sale` хранятся в taxonomy `equipment_mode`.


### Страница контактов

`/contacts/` — обычная WordPress-страница с шаблоном `page-contacts.php`, полностью ACF-only.

ACF-вкладки:
- **Главный экран** — H1;
- **Контакты и форма** — описание и переключатель видимости;
- **Карта** — переключатель видимости и режим «Картинка / Яндекс.Карта».

Телефон, e-mail, адрес офиса и соцсети не дублируются в странице и берутся из глобальных настроек **«Сайт»**.

Форма работает через общий Contact Form 7.

Для карты:
- по умолчанию используется изображение из утверждённой верстки;
- при выборе Яндекс.Карты используются глобальный API-ключ и координаты страницы;
- внешний API подключается только если интерактивная карта реально включена.

### Терминология ACF

В клиентской админке не используем термин **Hero**. Первый крупный блок страницы называется **«Главный экран»**. Это правило применяется ко всем существующим и следующим ACF-группам.


### Публичные URL оборудования

Публичного URL `/equipment/` в макетах Figma нет и на сайте быть не должно.

Правило:
- `equipment` используется только в админке;
- archive отключён;
- single URL отключены;
- taxonomy `equipment_mode` непубличная;
- на фронте оборудование выводится только внутри страниц `/equipment-rent/` и `/equipment-sale/`.
